# Обработка ошибок API

Этот документ описывает, как бэкенд сообщает об ошибках, структуру ответа и возможные коды ошибок для каждого эндпоинта.

## 1. Структура ответа об ошибке

При возникновении ошибки (HTTP status code >= 400) сервер возвращает JSON следующего формата:

```json
{
  "errorName": "STRING_ERROR_CODE",
  "message": "Человекочитаемое сообщение об ошибке (можно показывать пользователю)",
  "errors": [
    // Опциональный массив деталей (обычно при ошибках валидации)
    {
      "field": "название_поля",
      "message": "описание ошибки для конкретного поля"
    }
  ]
}
```

### Поля ответа
*   **errorName** (`string`): Уникальный код типа ошибки. Используйте его для программной обработки на фронтенде (например, подсветка полей, показ специальных уведомлений).
*   **message** (`string`): Текст ошибки на русском языке.
*   **errors** (`array | null`): Список детализированных ошибок по полям. Присутствует, если `errorName` == `"VALIDATION_ERROR"`.
    *   `field`: Путь к полю, где возникла ошибка (например, `body.name`, `query.limit`).
    *   `message`: Текст ошибки валидации.

---

## 2. Общие коды ошибок

| Код (`errorName`) | HTTP Status | Описание | Действия фронтенда |
| :--- | :--- | :--- | :--- |
| `VALIDATION_ERROR` | 422 | Ошибка валидации данных (Pydantic). Неверный тип, отсутствующее поле, нарушение ограничений (max_length и т.д.). | Показать ошибки под соответствующими полями формы, используя массив `errors`. |
| `INTERNAL_SERVER_ERROR` | 500 | Непредвиденная ошибка на сервере. | Показать общее уведомление "Что-то пошло не так". |

---

## 3. Бизнес-ошибки (Справочник)

| Код (`errorName`) | HTTP Status | Описание |
| :--- | :--- | :--- |
| `CLIENT_NOT_FOUND` | 404 | Запрашиваемый клиент не найден в базе данных. |
| `PARENT_CLIENT_NOT_FOUND` | 404 | Указанный `parentId` ссылается на несуществующего клиента. |
| `CLIENT_ALREADY_EXISTS` | 409 | Клиент с таким `name` уже существует. |
| `CLIENT_ALREADY_EXISTS_BY_INN` | 409 | Клиент с таким `inn` уже существует. |

---

## 4. Ошибки по Эндпоинтам

### 4.1. `GET /api/clients` (Список клиентов)

| Код ошибки | HTTP | Причина |
| :--- | :--- | :--- |
| `VALIDATION_ERROR` | 422 | Некорректные query-параметры (например, `limit` > 100, `offset` < 0, невалидный UUID в фильтрах). |

### 4.2. `GET /api/clients/{id}` (Один клиент)

| Код ошибки | HTTP | Причина |
| :--- | :--- | :--- |
| `CLIENT_NOT_FOUND` | 404 | Клиент с таким ID не существует. |
| `VALIDATION_ERROR` | 422 | Некорректный формат UUID в URL. |

### 4.3. `POST /api/clients` (Создание)

| Код ошибки | HTTP | Причина | Рекомендация UI |
| :--- | :--- | :--- | :--- |
| `VALIDATION_ERROR` | 422 | Обязательные поля не заполнены, превышена длина строк, неверный формат типов. | Подсветка полей формы. |
| `CLIENT_ALREADY_EXISTS` | 409 | Клиент с именем (`name`) уже есть. | Показать ошибку под полем "Название" или общий алерт. |
| `CLIENT_ALREADY_EXISTS_BY_INN` | 409 | Клиент с таким ИНН уже есть. | Показать ошибку под полем "ИНН". |
| `PARENT_CLIENT_NOT_FOUND` | 404 | Переданный `parentId` не найден. | Ошибка у селекта "Родительский клиент". |

### 4.4. `PATCH /api/clients/{id}` (Редактирование)

| Код ошибки | HTTP | Причина | Рекомендация UI |
| :--- | :--- | :--- | :--- |
| `CLIENT_NOT_FOUND` | 404 | Редактируемый клиент был удален кем-то другим. | Вернуть пользователя к списку, показать алерт. |
| `VALIDATION_ERROR` | 422 | Ошибка валидации обновляемых полей. | Подсветка полей формы. |
| `CLIENT_ALREADY_EXISTS` | 409 | Новое имя (`name`) занято другим клиентом. | Ошибка под полем "Название". |
| `CLIENT_ALREADY_EXISTS_BY_INN` | 409 | Новый ИНН занят другим клиентом. | Ошибка под полем "ИНН". |
| `PARENT_CLIENT_NOT_FOUND` | 404 | Новый `parentId` не найден. | Ошибка у селекта "Родительский клиент". |

### 4.5. `DELETE /api/clients/{id}` (Удаление)

| Код ошибки | HTTP | Причина |
| :--- | :--- | :--- |
| `CLIENT_NOT_FOUND` | 404 | Удаляемый клиент уже не существует. |

### 4.6. `GET /api/regions` (Справочник регионов)

Ошибок не ожидается, кроме стандартных 500 при падении базы.
