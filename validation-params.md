# Правила валидации входных данных API

Этот документ предназначен для фронтенд-разработчиков. В нем описаны точные правила валидации, которые применяются на бэкенде.
**Рекомендация:** Реализуйте аналогичную валидацию на клиенте (например, с помощью `zod` или `yup`), чтобы предотвратить отправку заведомо некорректных запросов.

---

## 1. GET /api/clients (Список клиентов)

Параметры передаются в строке запроса (Query Params).

| Параметр | Тип | Обяз. | Значение по умолчанию | Правила валидации / Допустимые значения |
| :--- | :--- | :--- | :--- | :--- |
| `query` | `string` | Нет | `null` | Текстовая строка. Без жестких ограничений по длине (в рамках URL). |
| `limit` | `integer` | Нет | `20` | • Минимум: `1`<br>• Максимум: `100` |
| `offset` | `integer` | Нет | `0` | • Минимум: `0` |
| `partyType` | `enum` | Нет | `null` | Только значения: `individual`, `legal` |
| `sortBy` | `enum` | Нет | `createdAt` | Значения: `createdAt`, `updatedAt`, `clientId`, `name`, `fullName`, `partyType`, `inn`, `regionId`, `parentId` |
| `sortOrder` | `enum` | Нет | `desc` | Значения: `asc`, `desc` |
| `regionId` | `UUID` | Нет | `null` | Строка валидного формата UUID (v4) |
| `parentId` | `UUID` | Нет | `null` | Строка валидного формата UUID (v4) |

---

## 2. POST /api/clients (Создание клиента)

Параметры передаются в теле запроса (JSON Body).

| Поле | Тип | Обяз. | Правила валидации | Сообщение ошибки (Frontend suggestion) |
| :--- | :--- | :--- | :--- | :--- |
| `name` | `string` | **Да** | • Не пустая строка<br>• Максимальная длина: **255** символов | "Введите название (до 255 символов)" |
| `partyType` | `enum` | **Да** | • Значения: `individual` или `legal` | "Выберите тип стороны" |
| `fullName` | `string` | Нет | • Максимальная длина: **512** символов<br>• Может быть `null` | "Максимум 512 символов" |
| `inn` | `string` | Нет | • Максимальная длина: **12** символов<br>• Может быть `null` | "ИНН не должен превышать 12 символов" |
| `regionId` | `UUID` | Нет | • Валидный UUID или `null` | - |
| `parentId` | `UUID` | Нет | • Валидный UUID или `null` | - |

> **Примечание:** Бэкенд проверяет уникальность пары `name` и `inn`. Эти проверки происходят только на сервере.

---

## 3. PATCH /api/clients/{id} (Редактирование)

*   **URL Parameter:** `id` должен быть валидным UUID.
*   **Body:** JSON объект. Все поля являются **опциональными**. Передаются только те поля, которые нужно изменить.
*   **Правила валидации:** Полностью совпадают с правилами для `POST /api/clients`.

| Поле | Тип | Обяз. | Правила (если поле передано) |
| :--- | :--- | :--- | :--- |
| `name` | `string` | Нет | Max длина: 255 |
| `fullName` | `string` | Нет | Max длина: 512 |
| `partyType` | `enum` | Нет | `individual`, `legal` |
| `inn` | `string` | Нет | Max длина: 12 |
| `regionId` | `UUID` | Нет | UUID или `null` |
| `parentId` | `UUID` | Нет | UUID или `null` |

## Рекомендации по реализации на клиенте (Zod Schema Example)

```typescript
import { z } from "zod";

export const ClientSchema = z.object({
  name: z.string().min(1, "Обязательное поле").max(255, "Слишком длинное название"),
  fullName: z.string().max(512, "Слишком длинное значение").nullable().optional(),
  partyType: z.enum(["individual", "legal"]),
  inn: z.string().max(12, "ИНН макс. 12 символов").nullable().optional(),
  regionId: z.string().uuid().nullable().optional(),
  parentId: z.string().uuid().nullable().optional(),
});
```
