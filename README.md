# Clients Management App

Frontend-часть тестового задания: приложение для управления базой клиентов.

## 🚀 Быстрый старт

### Требования
- Node.js 18+
- Доступ к работающему Backend API (FastAPI)

### 1. Настройка окружения
Приложение ожидает URL бэкенда в переменных окружения. Скопируйте пример конфига и при необходимости укажите в нём актуальный адрес API:

```bash
cp .env.example .env
```

### 2. Запуск приложения
```bash
# Установка зависимостей
npm install

# Запуск в режиме разработки
npm run dev
```
Приложение откроется по адресу: `http://localhost:5173`

## ✅ Что реализовано

Полностью выполнены все пункты технического задания:
- **Список клиентов**: Таблица с серверной пагинацией, сортировкой и индикацией загрузки.
- **Фильтрация**: 
    - Поиск по тексту (`query`) с дебаунсом (500ms).
    - Выбор родительского клиента (динамическая загрузка при открытии).
    - Выбор региона (загрузка один раз и кэширование).
    - Выбор типа стороны (статичный список на константах).
- **CRUD**:
    - Создание и редактирование клиентов через модальные окна.
    - Удаление клиента с подтверждением.
- **Валидация**: Интеграция `React Hook Form` + `Zod`. Обработка ошибок бэкенда (дубликаты по Имени/ИНН) с подсвечиванием полей.
- **URL-синхронизация**: URL является единственным источником правды для всех фильтров и пагинации.

## 🏗 Архитектура и Ключевые решения

### 1. Управление состоянием (Data Flow)

Проект минимизирует использование глобальных сторов в пользу специализированных инструментов:

- **URL State (`react-router-dom`)**: Используется как **Single Source of Truth** для фильтров, пагинации и сортировки. Это позволяет сохранять состояние при перезагрузке и делиться прямыми ссылками.
- **Server State (`TanStack Query`)**: Управляет кэшированием данных, дедупликацией запросов и инвалидацией.
- **UI State**: Локальный `useState` для временных данных (модалки, дебаунс).

### 2. Оптимизация
- **Clean URL**: Из адреса удаляются параметры, значения которых равны дефолтным (например, `offset=0` или `limit=20`), что делает ссылки чистыми.
- **Smart Selects**: Реализована разная логика для селектов: `staleTime: Infinity` для регионов и принудительный `refetch` (каждый раз) для родительских организаций.
- **Strict Typing**: Внедрена константа `PARTY_TYPES` как единый источник значений для TypeScript, Zod и UI-компонентов.

## 💬 Ответы на вопросы из ТЗ

> **Как другие компоненты будут получать обновления из store?**

В данной архитектуре нет классического глобального стора. Обновления происходят реактивно:
1. Компонент (например, фильтр) меняет **URL**.
2. Хук `useClientsFilters` видит изменения и обновляет объект фильтров.
3. React Query видит изменение ключа в `useClients(filters)` и автоматически запускает новый запрос.
4. Все зависимые компоненты получают свежие данные из кэша.

> **Какой вариант вы считаете оптимальным для данной фичи и почему?**

Связка **React Query + URL Params**. Для табличных данных с фильтрацией это стандарт индустрии, так как это избавляет от написания сложного кода синхронизации стейта, который уже реализован в браузере и библиотеках кэширования.

> **Обновление списка после create/edit?**

Выбрана стратегия **Invalidation** (`invalidateQueries`). В таблицах с серверной сортировкой и пагинацией это единственный надежный способ гарантировать, что измененный элемент окажется на правильной странице и в правильном порядке.
